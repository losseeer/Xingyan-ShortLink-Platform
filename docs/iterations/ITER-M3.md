## 4. 与设计的偏差及回写

| 偏差点 | 原因 | 处理（改代码回 DESIGN / 改 DESIGN 记录现状，注明小节） |
|---|---|---|
| **活体测试与部署中的 consumer 抢同一个 topic，让新字段的断言随机翻车**：`ClickPipelineLiveTest` 第一次跑就报 `click_id 应随事件落库，实际读到 ['', 'c-6bc…']` | 测试进程自己写一遍、容器里的 consumer 也消费一遍；两方对同一 `(short_code, click_time, event_id)` 写内容不同的行（旧 jar 不写 click_id），`ReplacingMergeTree` 的 `FINAL` 去重时**随机留一份**。以前两边内容完全相同所以看不见，新加列把它暴露了 | 不是产品缺陷，先按 DDL 注释里那条顺序把容器更新到新版本（`make images && make up`）再判，随后 125 测全绿。教训记进 §5：**给已有表加列时，"新旧写入方并存"是常态**，测试断言要么避开共享 topic，要么先对齐版本 |
| 验收脚本里的取值用 python 正则，双引号内再套单引号字符类，`'` 提前闭合字符串 → 提取恒为空、断言恒失败 | 报错长得像"数据不对"（`FAIL click-id-extracted`），实际是 shell/python 引号打架；同类坑在 bench 的 `run-jump-diagnosis.sh` 也记过一次 | 改用 bash 自己的参数展开 `${LOC##*xy_click_id=}` + `${CID%%[#&]*}`，并在注释里写明"别在这里嵌 python"。同时第一版正则 `[^&]+` 会把 fragment 的 `#top` 一起吞进来（`xy_click_id` 恰好是 `#` 前最后一个参数），字符类要同时排 `#` 与 `&` |
| 上一轮新加的"reload 后核对上游分布"脚本**自己就是那个假通过**：`docker compose ps -q jump` 报 `no such service: jump`（服务名是 `jump-1`/`jump-2`），期望集合为空 → "全部命中"通过，同时日志窗口里混着 reload 前的旧 IP，光数"出现几种地址"也偏松 | 检查脚本若只数种类，一个实例真坏了也可能凑够 2 种（旧地址还在窗口里） | 改成拿**当前**容器 IP 逐个比对，且取不到期望集合时**直接 exit 1**（不给自己"跳过即通过"）。改完立刻打印出真实地址：`172.18.0.6:8020 172.18.0.7:8020` |
| **构建工具"消失"是虚惊一场**：`make verify` 报 `mvn: No such file or directory`，我一度判断 maven 被卸载并向用户求证 | 用户交互 CLI 里 `mvn` 正常——它在 `~/maven/bin`，由 `~/.zshrc` 加进 PATH，而 **`.zshrc` 只有交互式 shell 才读**，工具起的非交互 shell 拿不到 | 构建类命令显式 `export PATH=/Users/dedsecczk/maven/bin:$PATH`（已写进本机环境记忆）。教训：工具链报"不存在"时先分清是**环境没加载**还是**真没装**，别急着改动用户环境 |

## 5. 本期决策记录

- **M3 从"补一个字段"开始，而不是从看板开始**：看板要展示的转化率、对账脚本要算的差异率，都依赖"点击 ↔ 订单"能被同一个键连起来。缺这个键时先做看板，等于给一个空列画图表。
- **只加一列 `click_id`，不加 `trace_id`**：订单回传带的就是 `xy_click_id`（DESIGN 附录 B 已定），它是唯一有对外语义的对账键；`trace_id` 是内部日志贯通用的，落库了对账也用不上，多一列就多一份要维护的口径。
- **不加跳数索引**（用 §3 那组数字判的，而不是"感觉会慢"）：点查 0.3–0.5s、批量 `IN` 1000 个 0.8s，对账是离线批处理，这个量级完全够；换成加索引要为 4.33 GiB 历史 parts 重写一遍。要复现：`clickhouse-client --time --query "SELECT count() FROM xsl.click_event WHERE click_id='…'"`，读量看 HTTP 头 `X-ClickHouse-Summary`。
- **被频控拦下的点击写空串而不是造一个 id**：那一击压根没生成跳转目标，编一个 id 会让对账以为它到过落地页。代价是"历史行"与"被拦击"共用空串，区分方式（看 `risk_score=25`）写进 DESIGN 4.2 与 `accept-m2-13` 的 E2 断言。
- **发布顺序写进 DDL 注释**：先加列（幂等 `ALTER`）→ 再换 consumer → 最后换 jump。反过来会有一个"新 jump 已经在发 `click_id`、列还不存在"的窗口，而 ClickHouse 的 `JSONEachRow` 对未知字段默认直接报错，那段时间的事件会写不进去。
- **历史行不回填**：那个值从来没进过消息体，回填等于造数据。
